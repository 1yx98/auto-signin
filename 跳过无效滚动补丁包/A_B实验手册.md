# A/B 对照实验手册 —— 「跳过无效滚动」补丁（P2）到底省了多少时间

> 目的：用**真实签到**跑一次对照，量出 P2 补丁的真实效果，而不是"我说它省 40 秒"。
> 实验期：**2026-09-17（周四）拆掉跑 → 2026-09-18（周五）装回跑**。

## 一、为什么要做这个实验

P2 补丁声称"已签到态下跳过 6 轮无效滚动，省约 40 秒"。
但这个数字来自**事后看日志推算**（6 轮 × 约 7 秒），**没有对照**。

而本项目有一条铁律（README 铁律 R11）：
**"合成样本只能验逻辑分支，真实效果只能靠真实样本。"**

所以：拆一天、装一天，拿两天真实的 `run.log` 对比。
这是唯一能分清"变化是补丁带来的"还是"本来就该这样"的办法。

## 二、实验怎么排

| 日期 | P2 状态 | 目的 |
|---|---|---|
| **09-17 周四** | **拆掉**（只留 P1） | 对照组：看"没有 P2"时第 4 步实际多久 |
| **09-18 周五** | **装回** | 实验组：看"有 P2"时省了多少 |

⚠ **只拆 P2，别拆 P1。** P1（滚动等页面变化）是另一个修复，
它也在影响第 4 步的耗时，两个一起拆就分不清是谁的功劳了。

⚠ **实验期间不要手工编辑 `signin.py`。**
跨包防护（自查判据）会把"手工编辑"也当成冲突，拆卸时会被拦。

### ★ 09-16 21:45~21:53 已做过一次「同场景预演」（结论已经很清楚）

用户要求当场对照，于是相隔 7 分钟跑了两次，**唯一变量就是 P2**：

| 指标 | 21:45 **装着 P2** | 21:50 **拆掉 P2** | 差异 |
|---|---|---|---|
| **「页面未变化」条数** | **0 条** | **5 条** | ✅ 6 轮白滚消失 |
| **`滚动前预检` 命中** | **1 条** | **0 条** | ✅ 补丁确实在/不在 |
| 第 4 步滚轮 | 跳过 6 轮 | 滚满 6 轮 | ✅ |
| **总耗时** | **89.2 s** | **138.8 s** | **−49.6 s** |
| 最终结果 | `not_time` | `not_time` | ✅ **一致** |
| 异常 / `FAIL_*.png` | 0 / 0 | 0 / 0 | ✅ **无副作用** |

**关键那行日志（有 P2 时才会出现）**：
```
21:46:53 [INFO] [导航] 第4步「每日签到里的进入按钮」滚动前预检：
         页面已是'已签到/已结束'态，跳过 6 轮无效滚动（省约 40 秒）
```

省下 **49.6 秒**，与"省约 40 秒"的预估吻合（略高）。
**且结果不变、无异常** → P2 的三条承诺（探得到 / 省得下 / 不捣乱）全部验证。

> ⚠ 这次预演是**超时段（21:45+）**场景，路程比正常签到短，
> 所以它证明的是"**这 6 轮白滚确实被省掉了**"（这是因果，可靠），
> **不能**当作"平时能省 49.6 秒"的完整证据 —— 那还要看 09-17/09-18 在时间窗内的两天。

## 三、09-17 周四：拆掉 P2

**前提**：目前的装在状态是 P1a+P1b+P2a+P2b，`signin.py` = `ed1f161e…`。

P2 不能整包拆（它的基线就是"装了 P1 的版本"），**必须逐条拆**：

```
:: 在项目根目录开命令行
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py revert P2b
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py revert P2a
```

拆完**必须核对**：

```
runtime\python.exe -c "import hashlib;print(hashlib.sha256(open('signin.py','rb').read()).hexdigest())"
```
输出的 sha256 **应该正好是 `2f2d675c081eea05e2ee94de6692f7a8c4e8c38653fbe0e4a02b3d65aeaa1ee3`**
（= 只装了 P1 的那个版本）。不是这个值就停下来查。

⚠ **注意 `list` 的显示会骗人**（2026-09-16 实测踩到）：
P1 的 `_state.json` 里 `installed` 可能显示"未装"，
但**文件里 P1 的代码其实在**（因为逐条 `revert P2a/P2b` 不会动 P1 的记录）。

**所以判"P1 还在不在"要看文件，不要看 `list`**：

```
runtime\python.exe -c "src=open('signin.py',encoding='utf-8').read();print('P1a:', 'def _scroll_fingerprint(' in src);print('P2a:', 'def _already_signed_detail(' in src)"
```
预期：`P1a: True`、`P2a: False`。

这条对应本项目铁律 **"记录服从事实"**：`_state.json` 只是记录，文件内容才是事实。

最后跑一遍测试套件确认没破坏现状：

```
runtime\python.exe smoke_test.py
```
预期：**158 项全过**。

然后照常等 20:50 的定时任务跑。

## 四、09-18 周五：装回 P2

```
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py apply
```
核对 sha256 应回到 `ed1f161e500fc2a7f2a54528ed9b7932f013fa5fe80a316269afb9e3d01410fd`。
再跑一次 `smoke_test.py`（158 项全过）。

## 五、要记录哪些数据

每天签到跑完后，**从当天的日志和 run 目录里抄这 4 个数**：

| 指标 | 从哪看 | 为什么它是关键 |
|---|---|---|
| **① 第 4 步耗时** | `logs/run_YYYYMMDD_HHMMSS/run.log` 里"第4步"到"第5步"之间 | **主指标**：P2 影响的就是这一步 |
| **② "页面未变化"出现次数** | 同上，搜这个串 | 对照组应该是 **6 次左右**；实验组应该是 **0 次** |
| **③ 总耗时** | 台账/日志里的总秒数 | 辅助指标（会被网络波动干扰，仅作参考） |
| **④ 最终结果** | `success` / `fail` / `not_time` | **安全指标**：如果结果变差，一切免谈 |

### 怎么快速取这几个数

```
cd D:\签到系统
:: 找到最近一次运行目录
ls -dt logs/run_* | head -1

:: 看第4步的日志
grep -n "第4步\|第5步\|页面未变化\|预检" logs/run_XXXX/run.log
```

如果实验组（09-18）能看到这一行：
```
[导航] 第4步「...」滚动前预检：页面已是'已签到/已结束'态，跳过 6 轮无效滚动（省约 40 秒）
```
那就说明**预检生效了**。这是最直接的证据。

## 六、结果怎么解读

| 情况 | 说明什么 | 怎么办 |
|---|---|---|
| 实验组"页面未变化"= 0 且第4步明显变短，结果仍 `success` | **补丁有效且安全** | 继续试用，到 2~3 天后嵌入主程序 |
| 实验组仍有"页面未变化"，只是少了 | 部分生效 | 看是不是那天不是"已签到态"（第一天签到的情况） |
| **实验组结果变成 fail / not_time** | **补丁有问题** | **立即拆掉 P2**，把 run 目录和日志给我，我来看 |
| 两天都是"第一天签到"（页面本来就没签到） | 样本不对等，无法对比 | 再等一天，等出现"已签到态"的那天 |

⚠ **最重要的判据是 ④ 最终结果。** 只要结果变差，其他数据再好都要拆。
这条对应 README 铁律 R8：**判错方向代价不对称 → 选"宁可暴露问题"那边。**

## 七、万一出问题怎么快速回滚

**一键回滚**（先拆 P2，恢复到 09-17 的状态，此时脚本行为与今天完全一样）：

```
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py revert P2b
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py revert P2a
```

**彻底回滚到最初原版**（两个包都拆干净）：

```
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py revert P2b
runtime\python.exe 跳过无效滚动补丁包\patch_engine.py revert P2a
runtime\python.exe 补丁包\patch_engine.py revert
```
拆完后 `signin.py` = `af3865177324d8a5…`（真正的原版，逐字节）。

⚠ 顺序不能颠倒。先拆 `补丁包` 会被跨包防护拦住（这是设计，不是故障）。

## 八、实验结束的判断

连续 **2~3 天** 都满足：

- 结果稳定 `success`（或正常的 `not_time`，即"今天还没推送"）
- 没有 `FAIL_*.png`
- 实验组的"页面未变化"明显少于对照组

→ 就可以走**毕业流程**：把 P2a+P2b 的代码**嵌入主程序**，然后**删掉整个补丁包目录**。
嵌入的具体位置和注意事项见主 `README.md` §7.10（那里有精确行号和"不许动哪几行"的警告）。
