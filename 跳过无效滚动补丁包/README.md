# 跳过无效滚动补丁包 —— 可插拔修复模块 P2

> 建于 2026-09-16 21:25。设计目标：**不改主程序，就能装载修复；出问题能整包拆掉，回到装载前的原样。**

## 这个包修的是什么

**症状**：签到流程走到第 4 步（"进入签到页"）时，如果页面**已经是「已签到/已结束」态**，
那段"下滚 6 次找蓝色签到按钮"的循环会**必然全失败**，白耗约 **42 秒**
（实测：2026-09-16 那次成功签到，6 轮「页面未变化」共 61 次日志）。

**根因**：**已签到态下根本没有蓝色「签到」按钮**——按钮已经变成灰色。
但循环的模板匹配只找蓝色按钮，所以滚 6 次当然一次都匹配不上。
（这一点是靠**看截图**才确认的，不是靠读代码；代码看起来完全正常。）

**修法**：滚之前先探一下——如果详情页已经是「已签到/已结束」态，直接跳过这 6 轮。
怎么探？复用主程序**已有**的 `scan_buttons()` + `signed_detail_button()`，
判据与主程序完全一致，不引入第二套判据。

**探不到怎么办**：函数返回 `False`，流程**完全退化为原行为**（照旧滚 6 次）。
所以这条补丁**只会更快，不会更错**——它没有能力把"该成功"变成"失败"。

## 怎么用（双击 bat 就行）

| 脚本 | 作用 |

| `5_补丁引擎自检.bat` | 负向测试：把护栏改坏，确认它真的会拦住 |

也可以用命令行（在 `跳过无效滚动补丁包` 目录下）：

```
..\runtime\python.exe patch_engine.py check      # 校验
..\runtime\python.exe patch_engine.py apply      # 全部安装
..\runtime\python.exe patch_engine.py apply P2a  # 只装 P2a

```

## ★ 本包以"当前文件"为基线（重要）

本包安装时的 `_backup/signin.py.base` **不是**最初的原版 `signin.py`，
而是 **"已经装了 `补丁包`（P1a+P1b）的那个版本"**（sha256 `2f2d675c…`）。

**为什么要这样**：两个补丁包改的是**同一个** `signin.py`。
如果新包以"原版"为基线，拆卸时整包覆盖会把 P1a+P1b 一起抹掉。

**代价**：本包**不能单独拆卸**——拆它会连带 P1 一起没。
所以本包的实际拆卸姿势是：

```
先拆本包（跳过无效滚动补丁包）→ 再拆 P1（补丁包）
```

或者干脆两个包都拆掉，再按需重装。反正 P1 的基线是真正的原版，
`补丁包/patch_engine.py revert` 拆完就是**逐字节原版**，这是最干净的姿势。

## ★ 跨包冲突保护（2026-09-16 真实事故后加的）

**事故**：21:26 执行 `补丁包/patch_engine.py revert`（想拆 P1），
结果输出"已全部拆卸，signin.py 恢复为基线"，**把本包的 P2a+P2b 一起抹掉了**——
而本包的 `_state.json` 仍显示"已装"。

**根因**：整包拆卸 = 用**自己的**基线整体覆盖文件。
`补丁包` 的基线是原版，覆盖回去当然把后装的 P2 冲掉了。
当时已有的"跨包防护"只查注册表，而那会儿注册表机制**还没上线**，
`补丁包` 从没登记过，所以它以为"没冲突" → 放行。

**修法（两道判据）**：

| 判据 | 问的问题 | 拦住的情况 |
|---|---|---|
| ① 注册表交叉核对 | 别的包改过文件，且它的记录 sha ≠ 当前 sha？ | 常规的"另一个包也改过" |
| ② 本包自查 | **我上次改完登记的那个 sha，还是当前 sha 吗？** | 本包从没登记过、但确实有人在我之后动过文件 |

判据 ② 是关键补漏——它换一个角度问：
"**我还认得出这个文件吗？**" 认不出，就说明有人在我之后改过，**绝不能覆盖**。

**原则**：**宁可拆不掉，不可拆错。**

## 如果装上去发现问题怎么办

```
3_拆卸补丁.bat
```

但注意上面那条：**本包会因为跨包防护被拒绝拆卸**（如果 P1 还装着）。
被拒绝时它会打印清楚原因和下一步该怎么做。这是**设计如此，不是 bug**。
