# 不在区域内重跑补丁包 —— 可插拔修复 N

> 建于 2026-09-17。**修的是用户明确要求的那条**：
> 「如果遇到不在区域内重新跑一遍流程，然后去签到」

## 这个包修的是什么

**症状**：地图页显示灰色 **「不在区域内」**（PC 定位漂到校外）时，
脚本判 `not_time`（"不在签到时段/任务已结束，**并非失败**"）→ 外层重试循环
看到 `not_time` 就 `break`（日志原话「**重试无意义**」）→ **剩下 2 轮根本不跑**。

**2026-09-17 20:57 实测**（`run_20260917_205504`）：

| 截图 | 时间 | 内容 |
|---|---|---|
| `205642_step03_1_3_到达签到详情页.jpg` | 20:56:42 | 地图 + 「获取位置」 + 灰色「完成签到」 + 地址 `---` |
| `205657_详情页按钮扫描.jpg` | 20:56:57 | 定位完成 → **「不在区域内」** + 地址「陕西省西安市鄠邑区甘亭街道陕西省东街」 |

**真根因：PC 定位漂到校外**，底部按钮由绿变灰「不在区域内」。

### 两层危害

**① 误报正常状态**（违反铁律 R14）
「不在区域内」和「已结束/未开始」**都是灰色宽按钮**，阶段A 只看"有没有蓝/绿/灰"
→ 分不出来 → 把「定位漂移」当成「今天没推送」：
- 台账记 `not_time`（不是失败）
- 自愈不更新故障状态
- 飞书也报"并非失败"

**② 跳过了本来能救回来的自愈**
`signin.py` 阶段B（`click_sign_button` 之后的定位循环）**本来就有**完整的定位自愈：
- `tap_relocate()` —— 点地图右下角"回到我的位置"
- `reconnect_wifi()` —— 重连 WiFi 强制重算定位
- 连续 3 次重新定位不行就重连 WiFi

**但它们全在阶段B，而脚本在阶段A 就 return 了，一步都没走到。**

## 怎么修

| id | 做什么 |
|---|---|
| N1 | 注入 `_is_not_in_area()` —— OCR 读那个灰按钮的文字，命中「不在区域内/未在区域」即认定 |
| N2 | 阶段A 的判据加一个条件：**是「不在区域内」就不判 not_time**，并打日志 |
| N3 | 放行走到阶段B（而不是落到 `if not green:` 被判 fail），**让本来就有的定位自愈跑起来** |
| N4 | 阶段B 的日志如实说明是「不在区域内」而不是「已有绿色按钮」（原来那句话在这种情况下是假的） |

**★ 安全设计**：`_is_not_in_area()` **读不到 / 引擎不可用 / 任何异常 → 一律返回 False**
（铁律 R7：读不到 ≠ 坏的）。返回 False 时，**行为逐字等价于改动前**，
绝不引入新的误判。

**效果**：定位漂移时 → 走阶段B 定位自愈（重新定位 ×3 + 重连 WiFi）；
仍不行 → 返回 `fail` → **外层完整重跑一遍流程**（最多 3 轮），
就是用户要求的那条。**全程不再产生 `not_time`**，故障如实暴露。

## ★★ 开发中踩到的两个坑（都值得记住）

### 坑 1：`replace_lines` 只替换一行 → 旧函数体残留

第一版 N2 把 `if not green and gray:` 那一行换成了"新 if/else 块"，
**但原来的 3 行函数体还留在后面** → 形成「新逻辑后面又跟一段旧逻辑」，
旧逻辑照样 `return "not_time"`，**补丁等于没生效**。

而 `signatures` 只验"该有的在"，**验不出残留**；`expected_delta_lines` 也验不出
（残留属于原有行，不计入 delta）。**`smoke_test` 当时仍 158/158 —— 会静默上线。**

→ **修法**：改设计为「**只加条件、不动函数体**」，
并给引擎加 `absent_signatures`（声明"装完必须消失"的串）。
本次已加负向测试 ⑩ 并做变异验证（把校验改坏 → 用例⑩ 正确变 `摆设!!`）。

### 坑 2：一个补丁失败，后面的补丁仍会装上 → 留下未定义变量

N2 失败但 N3/N4 装上了 → `_not_in_area` 从未被定义 → **运行时 NameError**。
引擎只能查**语法**，查不出这种"变量没定义"。

→ **教训**：改完必须**核对最终代码结构**（本项目已有铁律：验证要落在事实），
不能只看"引擎说成功"。
